INTERNAL USE ONLY — CLEAR Staff

Purpose

This tool lets CLEAR staff register a whole group of people for a NOVI event at once, by uploading a spreadsheet of names and email addresses instead of entering each person individually in NOVI. Use it any time you need to register more than a handful of people for the same event — conference attendees, a workshop group, a committee, and so on.

The tool will, for each person in your list:

  • Check whether they already have a member record in NOVI, and link the registration to it if so.

  • Optionally create a new record in NOVI for people who don’t already have one — either as a Non-Member, or as a full Member (standalone or inheriting membership from a parent company).

  • Register them for the event under the correct ticket type, at that ticket’s real price.

  • Show you a clear pass/fail result for every person, so nothing silently fails.

IMPORTANT

This tool writes directly to CLEAR’s live NOVI database. Registrations, new member records, and the resulting ticket charges are real and immediate. Always review the preview table carefully before clicking Import.

Before You Start

Have these things ready before you open the tool:

  • Your Worker Auth Token — in 1Password, search “Auth Token” and copy the password.

  • The Event’s Unique ID (a GUID) from NOVI.

  • The Ticket UniqueID (a GUID) for every ticket type on the event — e.g. Member Rate, Non-Member Rate.

  • Your list of registrants, at minimum their email addresses. First Name, Last Name, Company, and Phone are strongly recommended — without them, matching and record creation are limited.

  • If any registrants are joining as new members under a parent organization, the Parent Company’s NOVI GUID for each one.

Process Guide

Step 1: Connection

This section connects the tool to CLEAR’s NOVI system. You shouldn’t need to change the Worker Base URL — it’s pre-filled.

Field What To Enter
Worker Base URL https://clear-lms-proxy.avance.workers.dev
Auth Token In 1Password, search “Auth Token,” copy the password, and paste it here. This token authorizes every action the tool takes for the rest of your session.

Step 2: Event & Ticket Types

This tells the tool which NOVI event to register people for, and which tickets are available — including their real prices and whether they’re restricted to members.

Finding the Event Unique ID

In NOVI:

  1. Navigate to the Event

  2. Click the Settings tab header

  3. Scroll down to the bottom of the page to Event API Info section

  4. Copy the UniqueID value.

  5. Paste it into the Event Unique ID field.

Finding the Ticket Unique IDs

In the NOVI event, for each ticket to be used in the import:

  1. Click the Tickets tab header

  2. Select the ticket

  3. Scroll to the bottom of the pop up and the Advanced section

  4. Copy the API UniqueID value.

  5. Paste it into the TicketUniqueID GUID field

Click “+ Add Ticket Type” for each additional ticket the event offers (e.g. Member Rate, Non-Member Rate), and paste the matching GUID into each row. As soon as you enter a GUID, the tool fetches that ticket’s real price from NOVI and shows it under the row — confirm the price shown matches what you expect before moving on.

TIP

The Label you type here must exactly match the TicketType column value in your CSV Template file, if you’re using that column. If it doesn’t match, or if you leave the CSV column blank, you’ll assign ticket types manually in Step 4 instead.

The "Member Only" Checkbox

Check this box on any ticket type that should only ever go to an actual member. Once checked, the tool will refuse to import anyone assigned that ticket unless they’re a confirmed member or inheriting member (see “Understanding Membership Status” below).

Step 3: Upload Registrant List

Click “Download CSV Template” to get a starter spreadsheet with the correct column headers, fill it in, save it, and upload it here. The only required column is Email — rows without one are skipped entirely, but without First Name, Last Name, Company, and Phone, matching and record creation are limited.

CSV Columns

Column Required? Notes
FirstName No Required if you plan to create a new record for this person — NOVI won’t create a record without a name.
LastName No Same as above.
Email Yes The only truly required column. Rows without an email are skipped entirely.
CompanyName No Shown on the attendee record if provided.
Phone No Shown on the attendee record if provided.
TicketType No Must exactly match a Label you entered in Step 2. If blank or unmatched, assign it manually in the preview table.
Purchaser No Pull the Unique ID for the purchasing user from NOVI (if other than the registrant.)

Any missing information can also be typed in directly on the preview screen after upload — you don’t have to get the CSV perfect before uploading.

Step 4: Preview & Assign Ticket Types

This is the main working screen. Every row from your CSV appears here, and First Name, Last Name, Company, and Phone are all editable directly in the table — click into any cell to correct or fill in a value at any time.

Bulk-assign ticket type to selected rows: If you didn’t include the ticket type in the upload, you have the chance to do it here. Select any rows you wish to assign to a ticket, select the ticket from the drop down menu and click the Apply to Selected button next to that menu.

Bulk-assign purchaser to selected rows: just as with the section above, you can assign the purchaser to all selected rows here. Copy the GUID from the Purchaser’s record in NOVI and enter it here then click the second Apply to Selected button. This is an optional step. If the purchaser field is left blank, it will default to the registrant.

Matching to Existing Members

Click the Match to Existing Members button. The tool checks each row’s email against NOVI directly and reports back one of the following in the Member Match column:

What You’ll See What It Means
Member: [Name] This person already has a NOVI record. Their registration will link to it automatically.
New Guest No matching record was found. You can leave them as a guest or select the create record checkbox to add them as a Non-Member or Member (see Step 4b).
Lookup failed The check itself hit an error (not the same as “not found”). Click “retry” next to the badge rather than assuming they’re not a member.

Matching runs in small batches with brief pauses between them to respect NOVI’s rate limit — for a large list, let it finish running before moving on.

Step 4b: Assign Membership Status for Unmatched Rows

This section only appears when at least one row came back “New Guest.” Use it when you want people who aren’t currently in NOVI to have a real record, rather than registering them as a one-off guest. Checking “create record” on a row expands a set of fields directly beneath that person.

Step What To Do
1 Make sure First Name and Last Name are filled in for anyone you plan to create a record for — NOVI requires a name.
2 Click Select All Unmatched (or check individual rows’ “create record” boxes) to expand their membership fields.
3 For each expanded row, choose Membership Status: Non-Member (default) or Member.
4 If Member: choose either a Member Type (for a standalone member) or a Parent Company GUID (for someone inheriting membership from an organization) — never both. Click Load Member Types first if the dropdown is empty.
5 Click Create Selected Records.
6 Confirm each row now shows “New Non-Member: [Name]” or “New Member: [Name]” before moving on to Import.

TIP

Member Type and Parent Company GUID are mutually exclusive. If this person is inheriting membership from a company, leave Member Type blank and fill in the Parent Company GUID instead — NOVI computes their membership from the parent link, not from a type on their own record.

The Member Type dropdown only shows types valid for an individual; company-only types are hidden automatically.

Step 5: Import

Once every row has a ticket type assigned (and you’ve reviewed the Member Match column), click “Import Selected Registrants.”

  • A progress bar and status column show real-time pass/fail for each person as the import runs.

  • If a Member Only ticket is assigned to someone who isn’t an eligible member, the import is blocked before anything is sent, with the affected names listed — fix their ticket or membership status and try again.

  • Each registration is charged at the ticket’s real price (fetched in Step 2) and marked Unpaid, so it shows in NOVI as an open balance rather than a completed payment.

  • If anyone fails, use Retry Failed Rows to try them again without re-running the whole batch.

  • Export Failed Rows to CSV downloads just the failures, with the error message included, so you can review or hand them off.

Understanding the Purchaser Field

In NOVI, every registration has a Purchaser — the record considered to have registered/paid for the attendee — separate from the Attendee themselves.

Leave the Purchaser field blank and the tool will automatically use the attendee’s own matched (or newly created) member record as the purchaser.

Only fill it in when someone else, such as the parent member, should be the purchaser of record instead of the attendee. You can enter either:

  • An email address — the tool looks it up in NOVI the same way it matches attendees.

  • A NOVI UniqueID (GUID) directly, if you already have it — this skips the lookup and applies instantly. (preferred)

If you have many people all purchased by the same person, use the “Bulk-assign purchaser to selected rows” field in Step 4 rather than typing it into every row — select the rows, enter the purchaser’s email or GUID once, and click Apply to Selected.

Understanding Membership Status & Ticket Restrictions

This section covers the difference between the two ways a new record can join NOVI, and how the tool decides who’s allowed to use a Member Only ticket.

Standalone Member vs. Inheriting Member

Situation What To Do
Standalone Member This person has their own individual membership. Select a Member Type from the dropdown and leave the Parent Company GUID blank.
Inheriting Member This person’s membership comes from a parent. Leave Member Type blank and enter the Parent Company’s GUID instead. NOVI computes their membership status from that link automatically.

Who Qualifies for a Member Only Ticket

When a ticket is flagged Member Only in Step 2, the tool checks each assigned row before allowing import:

  • A matched existing record qualifies only if NOVI reports their status as an active member or an inheriting member — simply having a NOVI record is not enough, since NOVI tracks Non-Members and Prospects in the same members table.

  • A newly created record qualifies only if you set its Membership Status to Member (with a type or parent company) during Step 4b — a newly created Non-Member does not qualify.

  • A row with no record at all (a plain guest) never qualifies.

TIP

If someone with a legitimate membership is unexpectedly blocked from a Member Only ticket, their NOVI status may use a value the tool doesn’t yet recognize as eligible. Note their name and status and flag it — don’t work around the block by unchecking Member Only on the ticket, since that would remove the protection for everyone else on the list too.

Troubleshooting

If You See… What To Do
“Lookup failed” badge The membership check itself hit an error — it does not mean the person isn’t a member. Click “retry” on that row.
“Row(s) don’t have a ticket type assigned” Every selected row needs a ticket type before you can import. Use the bulk-assign dropdown, or set each row individually.
“Missing a First or Last Name” when creating records NOVI requires a name to create a member record. Click into the First Name / Last Name cells for that row and fill them in, then try again.
“Member Type… don’t have a Member Type chosen” A row with no existing record is set to Member with no Parent Company GUID and no Member Type selected. Pick a type for a standalone member, or fill in the Parent Company GUID instead if they’re inheriting.
Import blocked for a Member Only ticket One or more selected rows aren’t confirmed members. Either change their ticket type, or go back to Step 4b and correctly match or create them as a Member before retrying.
A row fails during import with an error message Hover the “Failed” badge to see NOVI’s exact error message. Common causes are a missing ticket type or an invalid email format. Fix the row and use “Retry Failed Rows.”
Ticket price shows “price lookup failed” The tool couldn’t fetch that ticket’s price from NOVI. Double check the GUID is correct, then re-enter it to retry — import is blocked from using that ticket type until this resolves.
Import seems slow for a large list This is expected — the tool paces itself to respect NOVI’s rate limits so requests don’t get rejected. Let it finish rather than refreshing the page.

Important Reminders

  • This tool is for internal CLEAR staff use only.

  • Registrations and any records created — Non-Member or Member — are written directly and immediately to NOVI. There is no draft or undo step.

  • Each registration is charged at the ticket’s real price and marked Unpaid, showing as an open balance in NOVI — it does not mark anything as already paid.

  • Member Only tickets are enforced automatically based on NOVI’s own membership status — don’t disable that check to work around a blocked row.

  • When in doubt about whether to create a record for someone, or what Membership Status to give them, leave it unchecked and ask a supervisor — registering as a guest can be revisited later, but a created record is a permanent database change.
